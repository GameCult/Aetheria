## A. Aetheria Body

### A1. Sensing and visibility model as it stands (M)

Signatures and light
- `SignatureChannel` enum: Thermal, Reflection, DrivePlume, LaunchFlash, Emission (append-only, serialized). Sensing.cs:9-16. `Signature` struct = Channel, Strength, Item. Sensing.cs:18-32.
- Light sources: `Entity._visibilitySources` keyed by source object; sole writer `Entity.SetSignature` (Entity.cs:98-103), which throws for Channel Emission ("active emission, never a light signature"). Writers: Radiator (Thermal, Behaviors/Radiator.cs:121), Reflector (Reflection = CrossSection x Zone.GetLight, Behaviors/Reflector.cs:46), Thruster (DrivePlume, Thruster.cs:128), InstantWeapon/ConstantWeapon (LaunchFlash, InstantWeapon.cs:280, ConstantWeapon.cs:173), Visibility behavior (Visibility.cs:47), hull Thermal radiation (Entity.cs:1818).
- The detection track: each `Sensor.Execute` tick updates `Entity.EntityInfoGathered[entity]` per zone entity: passive gain `visibility x sensitivity x curve(angle/pi) x dt / distance`, ping gain `visibility x sensitivity x PingBoost x distance` once at wavefront crossing, both times `obscuration`; then `next *= 1 - TargetInfoDecay*dt` (Behaviors/Sensor.cs:159-228, Gain at :243-246). `entity.Visibility` is the single light number read here (Sensor.cs:200,213,221).
- Track membership: `VisibleEntities` gains an entity when EntityInfoGathered crosses `GameplaySettings.TargetDetectionInfoThreshold` upward, loses it crossing downward (Entity.cs:313-330). Settings: `TargetInfoDecay`, `TargetDetectionInfoThreshold`, `TargetArmorInfoThreshold`, `TargetGearInfoThreshold` (Settings.cs:223-227); `BearingMemory = 6` seconds (Settings.cs:221-222).
- A tracked entity is known exactly: nothing perturbs a position. `Contact.Bearing` is `normalize(subject.Position - Position)` while tracked (Entity.cs:953). FireControl reads true `target.Position` (FireControl.cs:295,409). Aim is gated on membership: `Designated` requires `source.VisibleEntities.Contains(target)` (FireControl.cs:296). (This is what ruling ew-owns-ambiguity-and-decoys names "exact track".)
- `PassiveInfo(position, signature)`: info a target would settle at under this entity's passive sensing = sum(gain_i)/(n * TargetInfoDecay); zero with no active sensor (Entity.cs:438-448). `ChunkInfo` reuses it for mining chunks (Entity.cs:425-430).

Reveals, Contact, Departure
- `Reveal` (item, channel, bearing, Time) held per (subject, item) in observer's `_reveals`; latest act replaces earlier; "Position is never carried: only the track gives it." Sensing.cs:77-94; `RecordReveal` Entity.cs:904-910 (bearing = normalize(subject - observer), item-less acts and non-zone subjects refused).
- `Entity.Sense()` (Entity.cs:963-1010): for each other ship, each item-bearing light signature with `Strength x PassiveInfo(other.Position, 1) > TargetDetectionInfoThreshold` records a reveal; ends reveals on perceived item destruction (`PerceivesDestroyed`, gated by TargetGearInfoThreshold, :914-916); handles `Departure`s (Sensing.cs:96-111; judged under the same light gate :989-997); prunes departed subjects' memory after BearingMemory (:998-1008).
- `ContactOf` (Entity.cs:938-955): Detected = tracked OR freshest reveal younger than BearingMemory; Tracked = membership of VisibleEntities; Classified = detected with any reveal; Identified = info >= TargetGearInfoThreshold; Bearing = true bearing while tracked else freshest reveal's bearing. Contact struct Sensing.cs:113-135.
- So positional ambiguity already exists in one narrow form: a reveal-only contact (not tracked) carries a bearing but no range, remembered 6 s (inferred from Entity.cs:951-953 + Sensing.cs:79). The ruling states this is "not EW and stays as ruled".

Paints and lock warning (M)
- `PaintMode {Search, Track}` (Sensing.cs:37-41). A ping crossing an entity in beam calls `entity.ReceivePaint(Entity, Item, PaintMode.Search, 0)` (Sensor.cs:196-199); `LockWeapon` calls `target.ReceivePaint(Entity, Item, PaintMode.Track, Lock)` while locking (LockWeapon.cs:~105 in M; EH adds the line after it). `ReceivePaint` queues a `PaintWarning(bearing, emitter class data, mode, strength)` (Entity.cs:892-896); `PublishInbox` publishes it next tick and ALSO records an Emission-channel reveal of the emitter's item (Entity.cs:869-881). So a painted ship always learns bearing, emitter class, search vs track (ruling sensor-stat-set item 4). `PaintWarning` Sensing.cs:61-75.
- HUD reads the strongest Track warning for the incoming-lock indicator (Gameplay/ActionGameManager.cs:1460-1475); Search paints are not shown there ("presented by contact-hud").
- Allies: a ping returns to faction allies as `PingReturn` (subject, illuminated range, illuminated obscuration, MaxRange), used for bistatic credit inside oval Rt x Rr < PingRange^2 (Sensor.cs:201-214; Sensing.cs:43-59); "an ally hears it silently ... no paint, no emission" (Sensor.cs:193-195).

Emissions heard and intercept factor (EH only; M lacks it)

Bearing only; feeds no track. (Entity.cs, Sensing.cs `ActiveEmission` struct in EH diff.) No listening gear exists in code yet: `HearingMultiple` is a constant 1/0 (EH).

Information consumers

So gathered info (EntityInfoGathered) directly scales hit probability: anything that lowers info lowers odds (inferred).
- Evasion/tracking: `PDeviation(evasion, Tracking)`, `Evasion(target, lineOfSight)`, `TrackingRate`/`PMount` (FireControl.cs:350-383, 420-427, 492-533). `TargetingSystemData` stats Accuracy, Resolution, Precision, Tracking (Behaviors/TargetingSystem.cs:20-43). These use true positions/velocities; no sensor-error term exists (inferred from reads at FireControl.cs:409-425, 513).
- Gear identification by info tier: `FireControl.IsRevealed` (FireControl.cs:164-183) uses Armor/Gear thresholds; separate from the Reveal book (rulings contact-reads-book-aim-reads-live superseded by reveal-ends-on-perception).
- Lock: `LockWeapon` lock growth `LockSpeed x pow(lerp(angle), DirectionImpact) x pow(EntityInfoGathered[target], SensorImpact)`; lock falls by `Decay` otherwise (LockWeapon.cs:~100-110); `Designated` rejects a LockWeapon that is not locked (FireControl.cs:297).
- Vapour cloud is the one obscuration; see A2.

### A2. Existing mechanisms that degrade or deny information (M)
- Vapour cloud: `VapourCloud` zone body (Position, Radius, Opacity, Lifetime, Venter; opacity fades linearly) - VapourClouds.cs:8-32. Adder: `Zone.Vent` (Zone.cs:296); only remover: `StepClouds` (Zone.cs:374-382); reader: `Zone.Obscuration(a,b)` = product of (1-opacity) over clouds whose disc touches segment a-b (Zone.cs:361-370). Owner of venting: `VapourDump` behavior, once per instance, stats Radius/Opacity/Lifetime (Behaviors/VapourDump.cs:32-60). Enters detection only through `Sensor.Gain`'s obscuration factor (Sensor.cs:184,200,213,221,255) and now, in EH, through emission hearing. It scales info, never moves a position. Ruling vapour-cloud-obscuration: "thins every sensor sight line through it by its opacity, both ways; locks fall by the existing threshold rule".
- Signature reduction: signatures are consequences of behaviors (thermal radiation from heat, drive plume from throttle, launch flash from firing). A ship hides by not acting/venting heat; lore calls this "heat debt" (A4). No explicit stealth/signature-mask stat exists at M (inferred: grep of Signature writers found only the six listed).
- Beam width: `SensorData.BeamWidth` limits a ping cone (Sensor.cs InBeam; ruling illuminator-beamforming). Ping cooldown/duration (`PingCooldown`, `PingDuration`) limit sweep tempo (Sensor.cs:32-39).
- Info decay: `TargetInfoDecay` drops info each tick; so a target out of passive reach falls out of VisibleEntities (Sensor.cs:223).
- Item destruction ends reveals only for observers with TargetGearInfoThreshold info (Entity.cs:914-916, :979-987).
- No jammer, decoy entity, spoofed bearing, false track, or position noise exists in code (greps for jam/decoy/spoof found nothing in ServerShared; "decoy" appears only in rulings/follow-ups and lore).

### B6. Real-world EW vocabulary (Wikipedia https://en.wikipedia.org/wiki/Radar_jamming_and_deception read, plus others)
- Noise jamming floods the receiver (spot, sweep, barrage), J/S ratio. Deception jamming sends false or contradictory signals; range gate pull-off drifts a false delayed return so the range gate leaves the target (page names it; defined at https://en.wikipedia.org/wiki/Range_gate_pull-off, SEARCH). Velocity gate pull-off is the Doppler analogue (SEARCH).
- Burn-through range: distance within which the target echo is strong enough to track despite jamming; depends on target RCS, jammer ERP, radar power, required J/S; lower RCS shrinks it.
- DRFM: receives the radar's energy and retransmits altered copies that can shift apparent range (delay), velocity (Doppler), or angle (sidelobe transmission).
- Chaff: reflective strips forming a cloud of false returns; near-zero Doppler makes it distinguishable from a real aircraft. Decoys: manoeuvrable objects with corner reflectors, sacrificial. Towed decoy or jammer keeps realistic Doppler and can lure an anti-radiation missile away (AN/ALE-55 named). Flares simulate IR output (SEARCH).
- Home-on-jam: anti-radiation missiles home on a jammer's emissions; a self-protecting jammer reveals its position; counters: stand-off jamming, decoys, towed jammers.
- LPI radar (https://en.wikipedia.org/wiki/Low-probability-of-intercept_radar, read): designed to avoid detection by passive receivers; echo falls with R^4 (two-way) while a receiver's one-way signal falls with R^2, so the receiver hears the radar before it sees the target echo - the asymmetry behind an "intercept factor" (the page does not use that term); LPI techniques: lowest power for the task, high duty cycle and long integration, wide bandwidth, frequency agility, coded pulses and pulse compression, low sidelobes, irregular scan.
- Passive coherent location (https://en.wikipedia.org/wiki/Passive_radar, read): uses reflections of non-cooperative transmitters; measures bistatic range, bistatic Doppler, direction of arrival; no emission, harder to jam; a single transmitter-receiver pair is much less accurate than conventional radar, multistatic improves it; mostly 2D.
